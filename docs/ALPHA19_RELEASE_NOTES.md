# v0.5.0-alpha.19

## WB-вход перенесён с VPS на телефон

Полевой запрос с VPS подтвердил `HTTP 498`, `server: wbaas` и
`status-no-id: PG-13-XS` для `https://stream.wb.ru/login`. Поэтому увеличение
тайм-аута и повторный серверный Chromium не являются исправлением: форма WB
может вообще не выдаваться IP дата-центра.

Основной поток WB теперь device-assisted:

1. администратор открывает **Провайдеры → WB Stream** и создаёт QR;
2. QR ведёт на публичную HTTPS-страницу панели, а одноразовый token остаётся во
   фрагменте `#` и не отправляется Nginx;
3. Android-клиент открывает WB во встроенном WebView на сети телефона;
4. после входа клиент извлекает только `wbx-refresh`, `x_wbaas_token`,
   `_wbauid`, `wbx-validation-key` и `wb_auth_api_device_id`;
5. значения отправляются Manager по HTTPS с 10-минутным bearer token;
6. Manager проверяет сессию через WB `slide-v3`, allowlist-фильтрует и атомарно
   сохраняет `/data/managed-secrets/cookies-wbstream.json` с mode `0600`.

Пароль панели, номер телефона, одноразовый код и cookies не находятся в QR,
status API или событиях. Pairing token хранится сервером только как SHA-256 и
удаляется после успеха, отмены или истечения времени.

## Android

- Добавлен отдельный готический экран WB-входа с WebView.
- Поддержан deep link `wlb://wb-login`.
- Публичная landing page пытается открыть приложение автоматически и оставляет
  ручную кнопку на случай блокировки redirect браузером.
- В настройках можно вставить скопированную одноразовую ссылку, если QR нельзя
  отсканировать тем же устройством.

## Полевой gate

1. Обновить Docker и Android до одной `v0.5.0-alpha.19`.
2. Открыть панель только через `https://panel.yozik.ru`.
3. Создать новый WB QR, отсканировать телефоном без другого VPN и завершить вход.
4. Убедиться, что панель показывает **Серверный WB готов**.
5. Создать WB-профиль и проверить реальный Creator до измерения скорости.
