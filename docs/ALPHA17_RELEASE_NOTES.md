# v0.5.0-alpha.17

## Встроенный вход WB Stream

- В разделе **Провайдеры** появилась отдельная карточка WB Stream.
- Панель открывает `stream.wb.ru/login` в одноразовом изолированном Chromium.
- Администратор вводит номер технического аккаунта и одноразовый код прямо в
  панели; старая Creator-программа и ручной `cookies.zip` больше не нужны.
- После входа Manager проверяет allowlisted WB cookies через `slide-v3`,
  сохраняет browser device ID как `__wb_device_id` и атомарно записывает
  `/data/managed-secrets/cookies-wbstream.json` с правами `0600`.
- Номер телефона и одноразовый код существуют только во время текущего входа:
  они отсутствуют в status API, событиях, логах и `control-plane.json`.
- Публичную панель необходимо открывать через HTTPS; при HTTP мастер показывает
  предупреждение о передаче номера и кода без TLS.

## Провайдерные профили Android

- Временная кнопка **В телефон** теперь работает для VK, WB Stream, Telemost и
  Dion, а не только для VK.
- Payload остаётся `v=1` и добавляет необязательный `provider`, поэтому старые
  VK-инвайты остаются совместимыми.
- Manager и Android связывают provider с allowlisted схемой/доменом call link;
  произвольный URL импортировать нельзя.
- Android распознаёт как `wbstream://<room>`, так и
  `https://stream.wb.ru/room/<room>`.

## UX и проверки

- Пустой cookie-файл `[]` больше не считается настроенным провайдером.
- Перед запуском профиля UI проверяет наличие credentials и переводит
  администратора в раздел **Провайдеры** с понятной ошибкой.
- Provider readiness проверяет необходимые имена cookies без раскрытия значений.
- Добавлены Go-тесты WB credential storage/API и Android unit tests provider
  detection/link validation.

## Ограничения

- Автоматическое получение новой ссылки из VK-уведомлений остаётся только для
  VK-профилей.
- Встроенный вход Telemost и Dion пока не реализован.
- Один Creator/звонок по-прежнему рассчитан на один активный Joiner.
