# WLB Manager panel

Панель запускает каждый Direct Creator как отдельный дочерний
непривилегированный процесс внутри контейнера. Docker socket ей не передаётся.
Она управляет постоянными клиентскими профилями и несколькими независимыми
сессиями: start/stop, platform, resources, KCP profile, join link, METRICS и
ограниченный журнал.

## Portainer

Создайте новый Stack из этого репозитория:

```text
Compose path: portainer-stack-panel.yml
```

Обязательные environment variables:

| Variable | Value |
|---|---|
| `PANEL_PASSWORD` | уникальный пароль длиной от 12 символов |
| `PANEL_USERNAME` | по умолчанию `admin` |
| `WLB_SECRETS_DIR` | `/opt/whitelist-bypass/secrets` |
| `WLB_IMAGE` | `ghcr.io/sereza111/whitelist-bypass-portainer:v0.5.0-alpha.22` |
| `MAX_SESSIONS` | общий предел Creator, по умолчанию `4` |
| `VK_PEER_ID` | цифровой ID VK-получателя новых ссылок |

Порт панели зафиксирован в Compose, чтобы развёртывание не зависело от
переменных Portainer:

```text
127.0.0.1:9200 -> container:8080
```

После Deploy Nginx проксирует `https://panel.yozik.ru` на loopback-порт 9200.
Браузер запросит `PANEL_USERNAME` и `PANEL_PASSWORD`. Во внешнем firewall
нужны TCP/80 и TCP/443; TCP/9200 открывать не нужно.

Начальный Nginx-конфиг находится в `docs/nginx-panel.yozik.ru.conf`. После его
установки команда `certbot --nginx -d panel.yozik.ru` получает сертификат
Let's Encrypt, добавляет HTTPS и HTTP→HTTPS redirect. Номер/код WB и пароль
Basic Auth нельзя вводить через HTTP.

## Cookies

Панель не загружает cookies через браузер. Она читает существующие read-only
файлы:

- `cookies-vk.json`;
- `cookies-yandex.json`;
- `cookies-wbstream.json`;
- `cookies-dion.json`.

Они остаются в `WLB_SECRETS_DIR` Docker host и не попадают в Git, API или
панельные логи.

### Вход провайдеров

Кнопка **Войти через QR** запускает одноразовый изолированный Chromium внутри
контейнера. Панель показывает снимок страницы входа VK, обновляет QR и ждёт
подтверждения с телефона не более четырёх минут. После входа Manager:

1. проверяет cookies через VK web token;
2. сохраняет их атомарно в `/data/managed-secrets/cookies-vk.json` (`0600`);
3. уничтожает временный browser profile;
4. использует управляемые cookies для всех новых VK Creator.

Пароль VK не вводится в панель. Старый read-only `cookies-vk.json` не
перезаписывается и используется как fallback после отключения QR-аккаунта.
Chromium включён в `amd64`/`arm64`; на `386` оставлен только файловый импорт.

Для WB Stream больше не требуется старая Creator-программа и ручной экспорт
архива. Нажми **Провайдеры → Подключить / сменить WB → Создать QR для телефона**,
отсканируй код актуальным Android-клиентом и войди в технический WB-аккаунт на
сети телефона. Это обязательный путь: WB возвращает `HTTP 498` для IP VPS.
Клиент передаёт по HTTPS только allowlisted cookies и `__wb_device_id` с
одноразовым bearer token. Manager проверяет сессию запросом `slide-v3` и
сохраняет `/data/managed-secrets/cookies-wbstream.json` с правами `0600`.
Pairing token находится после `#` публичной ссылки и не отправляется Nginx.

## Клиенты и хранение

- профили атомарно сохраняются в `/data/control-plane.json`;
- каждая сессия получает `/data/sessions/<session-id>`;
- у клиента есть enabled/disabled, срок действия и собственный лимит;
- один Direct Creator/звонок рассчитан на один активный Joiner;
- для каждого ПК, телефона или пользователя нужен отдельный профиль и сессия;
- выключение профиля запрещает новые старты, но не обрывает уже работающую
  сессию без явного `Стоп`;
- provider API показывает только наличие cookie-файла, но никогда его
  содержимое.

Обычному пользователю не нужен вход в аккаунт провайдера: серверный технический
аккаунт создаёт отдельный звонок для каждого профиля, а клиент входит как
гость. Для выдачи доступа создайте профиль, нажмите **Запустить**, дождитесь
ссылки и нажмите появившуюся кнопку **В телефон**. Панель создаст случайную
ссылку `/join/<token>` на 15 минут для VK, Telemost, WB Stream или Dion.
Android сверяет заявленный provider с разрешённой схемой/доменом call link,
открывает Whitelist Bypass, показывает подтверждение профиля и запрашивает
обычное VPN-разрешение. Личные cookies пользователя не запрашиваются и не
передаются на сервер. Временная ссылка является bearer secret; для публичной
выдачи используйте HTTPS reverse proxy.

## Текущие ограничения

- Basic Auth вместо полноценной session auth;
- профили переживают restart, история завершённых сессий пока не сохраняется;
- metadata хранится в JSON, без SQLite;
- ручной cookie upload для Telemost/Dion и QR-вход для них пока отсутствуют;
- нет TLS termination внутри manager;
- polling metrics вместо SSE;
- audit log пока отсутствует.

## Автоматическое восстановление VK

Профили по умолчанию создаются с **Автоматически восстанавливать звонок**.
Creator контролирует не только WebSocket звонка, но и состояние
PeerConnection:

- новый offer должен перейти в `connected` за 30 секунд;
- состояние `disconnected` получает 15 секунд grace period;
- `failed` и `closed` запускают recovery сразу;
- после трёх неудачных peer recovery процесс завершается, чтобы не остаться в
  формально живом, но нерабочем звонке.

Manager сохраняет логическую сессию, запускает новый Creator с backoff
`2s → 5s → 10s → 30s → 1m → 2m → 5m` и получает новую ссылку. Старые
RelayBridge, data/control KCP и logical flows при reset закрываются полностью.

Для доставки ссылки без VK-сообщества используйте отдельный VK-аккаунт для
server cookies, а в `VK_PEER_ID` укажите цифровой ID личного VK-аккаунта,
установленного на телефоне. Если server cookies принадлежат тому же аккаунту,
VK может не показать уведомление о собственном исходящем сообщении.

Первоначальную ссылку или pairing block выдаёт администратор из панели. Joiner
подключается к звонку как guest/анонимный участник: логин и cookies серверного
VK-аккаунта ему не нужны. Для каждого профиля можно задать собственного VK
получателя последующих обновлений.

Новая ссылка отправляется человекочитаемым сообщением с компактным `WLB2`
envelope и HMAC-SHA256. Android продолжает принимать старый `WLB1`. Секрет
создаётся отдельно для каждого профиля и не присутствует в VK-сообщении. В
панели:

1. запустите профиль и дождитесь состояния «Жду устройство»;
2. нажмите **В телефон**;
3. в Android нажмите добавление подключения и вставьте скопированный блок;
4. откройте **Settings → Automatic recovery** и разрешите приложению читать
   уведомления; в VK должны быть включены превью текста сообщений, иначе
   Android может не увидеть полный подписанный envelope;
5. подключитесь к созданному Android-профилю.

При следующей ротации Android принимает только сообщение с правильной
подписью и возрастающим generation, обновляет ссылку и автоматически запускает
переподключение. Открытые TCP-соединения могут перезапуститься, но пользователю
не требуется искать интернет и вручную заходить в панель.

Recovery key является секретом устройства. Не отправляйте блок сопряжения
другим людям и не публикуйте его в логах или Git.
